# ZERO EX 灯光控制 · WinUI 3

<img src="Assets/ZeroExLight.png" width="96" alt="ZERO EX Light 应用图标">

Windows 11 x64 原生 C# / WinUI 3 鼠标灯光控制工具，当前版本 **0.2.2**。支持已验证的 ATK ZERO EX 原厂固件 **3.01** 与随盒 NANO 2.4G 接收器。

提供“灯光控制”和“自定义”两个固定页签，支持青、红、绿、蓝、紫、黄、白七色选择，以及按顺序编排的循环渐变。退出默认保留最后应用的颜色，静置后仍由原厂固件休眠熄灯。

主要功能：

- 七色单次应用与原设置恢复；写入前备份，写入后读回核对。
- 最多 32 项颜色序列，支持重复颜色、拖放添加和排序。
- 每项独立设置停留和渐变时间，最后一项渐变回第一项。
- 无需连接设备的界面预览，以及本地编排自动保存。
- 鼠标静置约 2 秒后暂停自动发色，活动后继续；不轮询电量或发送保活。
- 默认退出保留最后颜色，可主动选择退出恢复原配置。

版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 环境要求

- Windows 11 x64。
- 运行已发布程序需要 .NET 8 x64 运行时；发布时 Windows App SDK 随程序携带。
- 从源码构建需要 .NET SDK 8.0.411 或兼容的 8.0.4xx 补丁版本，以及 Windows SDK / WinUI XAML 构建工具。SDK 选择由 [global.json](global.json) 约束。
- 项目依赖 Windows App SDK 2.5.1，通过 NuGet 还原。普通运行不需要管理员权限。

## 使用

1. 按下方说明构建和发布，保留完整发布目录，运行 `ZeroExLight.exe`。
2. 从系统托盘退出 ATK HUB。无线模式保留随盒 NANO 接收器，拔掉鼠标 USB-C 线。
3. 移动鼠标唤醒，选择“2.4G 无线接收器”，点击“连接鼠标”。连接时保存原始配置备份。
4. 选择颜色，点击“应用颜色”。只选色不会改变硬件。切换 DPI 档位后，可再次应用当前颜色到新档位。
5. 退出软件会保留最后设置的颜色。需要回退时点击“恢复原设置”，或主动勾选“退出时恢复连接前的灯光设置”。原始备份仍会保留。

设备休眠后，先移动唤醒再操作。若设备正在充电，红色充电提示可能覆盖设置的颜色；无线显示已实测。

## 自定义循环渐变

1. 打开“自定义”，把上方颜色拖入编排区域；也可以选中颜色后点“添加所选颜色”。同一种颜色可以重复添加，最多 32 项。
2. 拖动列表内的项目调整顺序，或选中后点“上移”“下移”。可移除单项或清空列表。
3. 选中一项，设置“停留时间”和“渐变到下一项”，单位为秒，各为 0–30 秒。最后一项会渐变回第一项。整轮总时长至少为 0.45 秒。
4. “界面预览”只在窗口里模拟，不连接或改写鼠标。编排自动保存到程序目录的 `Presets/custom-sequence.json`，下次打开可继续编辑，不会自动播放。
5. 使用 2.4G 并连接鼠标后，点“开始播放”。有鼠标活动时循环渐变；停止活动约 2 秒后暂停发色，移动鼠标后从暂停处继续。
6. “暂停”保留当前位置；“停止并恢复”结束播放并恢复原灯光配置。恢复时需让鼠标保持唤醒。播放期间停止编辑，停止后可继续修改。

窗口中的色块标为“序列预览”，表示计划显示的颜色，不是灯光传感器反馈。程序无法直接检测 LED 实际颜色。

退出软件后循环渐变停止，鼠标保留最后应用的颜色；软件不会在默认退出流程中向鼠标发送恢复或关灯指令。这不阻止鼠标休眠：静置后仍按原来的时间自动熄灯，移动唤醒后使用保留的灯光配置。保留颜色不表示已将自定义循环保存到鼠标固件中。

## 休眠必须熄灯

程序未播放、手动暂停或鼠标静置暂停时，不做自动 HID 查询、保活、发色或重连。电量仅在明确点击连接时读取，界面标为“连接时”。沿用鼠标的原有关灯和休眠参数。

自定义播放使用 Windows Raw Input 被动识别这只鼠标的移动和按键，不通过轮询鼠标维持唤醒，也不依靠键盘活动。没有鼠标活动约 2 秒后冻结播放位置并停止自动通信，让原厂固件按原来的时间熄灯。静置暂停不代表立即熄灯；本机原有关灯时间约为 60 秒。移动唤醒后继续播放。

本机 2026-10-25 实测：原有空闲关灯参数为 60 秒；设置青色后停止通信，静置超过 75 秒灯自动熄灭；移动唤醒后青色重新亮起。随后原始 96 字节配置完整恢复，168–191 的休眠相关参数也核对未变。后续活动控制渐变测试也得到用户“全部正常”的确认；正式 C# 播放器的循环渐变已由用户观察确认。该结果覆盖当前鼠标、3.01 固件、无线模式和当前设置，不把充电状态的红色提示算作自定义灯效。

## 备份和恢复

`Backups/` 位于程序目录。“查看配置备份”可打开它，目录必须可写。每次建立新会话保存 96 字节配置快照；这是相关配置备份，不是全固件备份。

`pending-session.json` 在写入前记录可能修改的地址。退出、断线或超时未完成恢复时，请保留此文件，下次使用原来的连接方式和配置档连接，再点恢复。接收器没有序列号时会使用设备路径匹配，因此恢复时宜使用原 USB 口。请保留整个程序目录及其备份，不要仅复制 EXE。

正常选择保留灯光退出时，恢复记录会标记 `RetainedOnExit=true`。下次连接会提示上次主动保留的灯光，仍可手动恢复最初的备份；不把主动保留当作恢复失败。再次写入或开始手动恢复前会清除该标记，以保留异常中断的恢复提示。

恢复只写入本程序修改过的颜色块和灯效块，不把整份快照覆盖回鼠标。请在同一时段只使用一个控制程序。

## 功能边界

- 只支持已经验证的 ZERO EX / 3.01 与 NANO 接收器，型号或版本不符即拒绝写入。
- 修改当前 DPI 档位的指示色，启用常亮；保留原亮度、速度、DPI 数值、回报率和休眠参数。
- 七色与渐变中间色已人工观察。实机发色间隔至少 450 毫秒，适合缓慢渐变，不承诺高帧率或音乐同步。
- 渐变目前使用已验证的配置写入通道，合并重复颜色，静置即停。尚未确认独立的实时 RAM 灯效命令及该配置通道的长期写入耐久性；目前验证的是短时功能。
- 保留官方固件；程序没有刷机、重新配对或重置命令。
- 明确操作及用户启动且鼠标有活动的播放期间才通信。睡眠中的设备可能无法回复，需移动唤醒。

## 从源码构建

在 Windows 上克隆仓库后，从项目根目录运行：

```powershell
dotnet restore -p:Platform=x64
dotnet build -c Release -p:Platform=x64
dotnet publish -c Release -p:Platform=x64 --no-build -o .\publish
```

项目的发布步骤会同时复制应用的 `.xbf` 和 `ZeroExLight.pri`；这些是窗口启动必需的编译资源，请保留。

`Assets/ZeroExLight.ico` 包含 16–256 像素的九个尺寸，供 EXE 与原生窗口使用；SVG 和 PNG 源文件也保存在 `Assets/`。重新生成图标是可选开发步骤，应用本身不依赖 Python：

```powershell
py -m pip install pillow cairosvg
py tools/create_icon.py
```

分发版本包含第三方运行库，相关组件的许可归各自权利人。

程序使用进程间单实例锁，避免两个窗口争用设备或覆盖恢复记录。窗口保留与显示缩放对应的最小宽度，较矮的屏幕可纵向滚动。

## 诊断

`--self-test <json路径>`：离线验证帧、校验和及禁止越界写入，不连接硬件。

`--probe <json路径>`：只读设备身份、版本和配置。

`--verify-protocol <json路径>`：向当前颜色块写回完全相同的值，核对原生写入路径和 96 字节配置未变；仅供开发验证，设备需保持唤醒。

`--capture <png路径>`：渲染本程序初始界面截图，不连接硬件。

`--verify-custom-ui <json路径>`：使用窗口中的真实控件和拖放数据格式，离线验证编排、预览、保存与页签状态，不连接硬件。

`--verify-custom-device <json路径>`：开发用短时无线渐变、静置无通信和恢复测试。需要人工观察，先轻移再放稳，最后按窗口提示唤醒完成恢复。

`--verify-retained-exit <json路径>`：开发用无线青色与真实窗口退出检查。会保留青色，记录退出前后命令计数和退出前配置；需要人工观察，并在进程退出后另行只读核对设备配置。
